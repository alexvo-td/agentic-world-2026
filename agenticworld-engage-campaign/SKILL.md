# Agentic World Engage Campaign

Default to the Plot-twist workshop stage: Northstar receives a conference list of existing customers with renewed contact and needs to activate it quickly. Carry forward Customer Discovery decisions. Use the supplied Northstar template, fictional 20% offer and sofa/rug/lamp unless the inherited brief establishes different approved content. New prospects need separately defined eligibility and acquisition copy; never manufacture purchase history to make them overdue. Support a standalone win-back mode when explicitly requested or no prior discovery exists.

## Definition language

Keep all skill definitions, metadata, reference instructions and example prompts in English. When editing these resources, translate non-English examples into English. This does not override the participant response-language rule below.

## Conversation contract

- Respond in the participant's language. Keep email copy in English unless requested otherwise.
- Accept business prompts without requiring a skill invocation: “Use the conference list with our selected Northstar strategy. Add my email for delivery confirmation, prepare the campaign and show its performance after launch.”
- Reuse explicitly supplied identity and current workfolder assets. Do not infer a recipient from an account name or a remembered identity.
- Ask for missing email, first name, and last name together in ONE ordinary message. Do not use AskUserQuestion, forms, or separate questions. Example: “To add you to the Northstar audience, send your email, first name, and last name. Your address will be a labeled workshop delivery-confirmation recipient, separate from customer targeting.” Ask only for missing values. Validate the reply and request only corrections if invalid.
- Execute read-only discovery immediately as part of the requested campaign preparation: workspace, sender and campaign listing/details, CLI help/version, configuration checks and status polling. Do not ask “May I run this read-only command?” or present a command approval block. Use a brief progress statement and execute.
- For each new campaign-preparation request, create a new campaign and a new audience/recipient table by default. Reuse an earlier campaign or audience only when the participant explicitly requests that reuse; permission to reuse one does not imply permission to reuse the other. Resume the same run for revisions, continuation and technical retries.
- Use the available AskQuestion/AskUserQuestion choice tool (or equivalent structured choice tool such as request_user_input) for audience, message direction and other business decisions with discrete options. Show 2–3 concise options, mark the recommendation and explain each option's effect. Keep identity intake in one ordinary message. Never use this choice tool to ask permission for technical commands. If no compatible choice tool is available, fall back to one concise ordinary-message choice question.
- In Plot-twist mode, present an added-list impact report under references/plot-twist.md: applicability, exclusions, verified overlap and messaging implications. Reuse the inherited audience choice; open a choice only for an unresolved business difference. In standalone mode, use references/audience-insights.md for the full audience comparison before selection. Distinguish observations from persona hypotheses and label fictional data in both modes.
- Reuse supplied/inherited audience, offer and messaging choices. In Plot-twist mode, recommend retaining the message or adjusting its opening only when the new list justifies a change. Show concrete before/after copy before a choice. In standalone mode, guide audience then message selection. Do not reopen settled decisions or silently apply unresolved settings.
- Automatically perform CSV update, synthetic data generation, runtime preparation and discovery. After business choices, automatically perform draft creation, mapping, template personalization and validation. Do not add technical approval or query-history consent questions.
- If the participant explicitly says to use all recommendations, skip business choice questions, apply the recommended settings and show the preview. Preserve the final Launch action.
- Present a completed campaign review report in AI Studio covering email content, personalization, audience, and sender/campaign settings. Save campaign-review.md and email-preview.html in the personal run folder and display them under launch-review.md. Obtain one explicit approval to launch that reviewed version. Present a completed preview before launch. Treat “Launch this campaign” after that preview as authorization for the reviewed send; do not ask again. An initial request to create a campaign is not launch authorization.
- Honor platform-enforced controls; these instructions cannot disable them.
- Never ask participants for SQL, IDs, runtime choices, mappings, secrets, merge-tag syntax, or synthetic attributes. Resolve technical gaps from host configuration and service discovery; if blocked, give a short host-facing remediation.

## Technical command authorization

Execute all task-required read-only `tdx` commands automatically, including sender discovery with `tdx delivery senders` (not the Engage namespace) and any `tdx ... --help` or version checks. Do not ask “Run them?” or request command permission. This applies across command namespaces, not only `tdx engage`. Read discovery output and continue. Keep business choice tools for marketing decisions only. Use documented `--yes` for authorized draft push; retain final business Launch before live sending.
